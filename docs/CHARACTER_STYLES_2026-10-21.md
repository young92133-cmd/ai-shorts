## 1. 구조

```
템플릿(templates/*.yaml: 배치·글꼴·기본색)  +  그림체(art_styles/*.yaml: 색·선·배경 표현·말풍선·컷·효과·인물 테두리)
        └─ load_template(template, fmt, art_style) 한 곳에서 합침 → 기존 렌더러가 그대로 그림
캐릭터(characters/<id>/bible.json, 같은 CharacterBible 형식)
  ├─ 그림 자산형: poses/*.png (햄토리치, 사용자 등록 캐릭터) — 감정·자세별 그림, 승인된 것만 사용
  └─ 앱 그림형: mascot 설정(머리·옷·피부색·face: cute|simple·선 굵기) → mascot.py 가 모든 감정을 그림 (토리·민지·도트)
```

- 그림체 선택: `make --art-style`, 스튜디오 새로 만들기 '그림체', 기존 작품은 '그림체·주인공 적용'(문구 그대로 전체 다시 그림, 실행 취소 가능).
  선택은 `plan.json` 의 `art_style` 에 남아 편집·실행 취소·다시 실행에도 유지된다.
- 같은 작품 안 일관성: 주인공은 한 캐릭터 id 로 모든 컷에 쓰이고, 앱 그림형은 같은 감정이면 항상 같은 그림(테스트로 확인), 그림 자산형은 승인된 포즈만 쓴다.
- 참고 이미지 그림체: `art-style --id --name --image …` → 색 구성·밝기·채도·선 비율만 재서 `assets/art_styles/<id>.yaml`. 그림 자체를 베끼지 않고, 이미지는 복사하지 않는다.
  Threads(@makmak.law) 게시물은 로그인 벽으로 볼 수 없어 추측하지 않았다 → 스크린샷을 받으면 이 명령으로 만든다.
- `default` 그림체 = 템플릿 그대로: 기존 결과와 **바이트 동일**(관리비 툰·신용점수 카드뉴스 16장으로 확인).

## 3. 적용 범위와 한계

- 그림체가 바꾸는 것: 앱이 그리는 모든 것(배경·컷·말풍선·효과·표지·카드 색·앱 그림형 캐릭터의 선). **그림 파일(햄토리치 포즈, 사용자 그림, 공개 사진)의 그림체는 바꾸지 못한다** — 흰 테두리만 더한다.
- 앱 그림형 사람 캐릭터는 단순한 평면 그림이라 햄토리치·참고 계정 수준의 완성도에 못 미친다. 높은 완성도의 사람 캐릭터는 **그림 자산**(직접 제작·외주·승인 후 AI 생성)이 필요하다.
- 측면(옆모습)은 그림 자산형에서 `pose: side` 포즈로 관리할 수 있지만, 앱 그림형은 정면 + 좌우 뒤집기만 있다.
- 카드뉴스의 배치는 그림체가 아니라 템플릿이 정한다(그림체 = 색·톤).
